# SCNSim collaboration

Human may work directly with **Lead — SCNSim Documentation** on reader-facing
information architecture, narrative, navigation, terminology and writing quality
in the README, guides and documentation.

**SCNSim Development** retains product meaning: runtime and public APIs, schemas,
formulas and scientific interpretation. It also owns docstrings, generators,
packaged-knowledge behavior, executable notebooks and teaching code, tests, CI,
packaging and release work. Documentation edits preserve those contracts and
research requirements; proposed semantic changes return to Development.

Assign one writer per exact path or hunk before editing shared `.qmd` files,
notebooks or configuration. Separate prose from executable cells, formulas,
contract statements and generated content. Preserve existing changes and active
writers; generated files are updated through their owning generator.

After an exact handoff, Documentation owns the existing documentation Preview
operation. Record its URL, host, command, working directory, process/session,
source revision, outputs and shutdown responsibility in the handoff. Preserve
the running service and process; Preview ownership remains separate from formal
publication by the existing publisher.

After each coherent documentation change, Documentation notifies Development
with the exact source identity and implementation-facing delta so Development
can check implementation consistency. Development decides any implementation,
semantic or test changes under the existing authority.

Development and the existing Integration service serialize Git delivery under
the selected delivery profile. A documentation handoff does not authorize a new
publisher, branch switch, merge or release. Use the applicable collaboration and
lifecycle Skills for delivery and verification requirements.
